# F02 冒煙驗收清單（拼多多＋千牛）

> 目的：確認「買家訊息 → 自動回覆成功」在兩渠道各至少一輪。  
> 前提：閘道已跑、Tenant 有餘額、桌面已登入閘道、`__main__.exe` 已放入 `apps/desktop/assets/backend/`（見 `USER_CHECKLIST.md`）。

## 共用前置

| # | 步驟 | 預期 | 通過 |
|---|------|------|------|
| 0.1 | 閘道 `http://127.0.0.1:8787/admin/` 可登入；ModelSKU 已啟用 | 後台可開 | ☐ |
| 0.2 | TenantAdmin（如 `demo_admin`）登入桌面「閘道帳戶」 | 顯示餘額 | ☐ |
| 0.3 | `tenant.html` 建好 Shop；`external_keys` 能對上實例 `shop_name` | 有至少 1 個 Shop | ☐ |
| 0.4 | 桌面實例卡片綁定該 Shop | 顯示「已綁 Shop」 | ☐ |
| 0.5 | 關鍵詞視窗可選所屬 Shop；至少一條素材關鍵詞 | 存檔成功 | ☐ |
| 0.6 | 開啟自動回覆（關鍵詞匹配＋閘道 AI） | 任務可啟動 | ☐ |

## A. 拼多多

| # | 步驟 | 預期 | 通過 |
|---|------|------|------|
| A1 | 新增拼多多實例並掃碼登入 | `login_status=logged_in`；瀏覽器不異常重開 | ☐ |
| A2 | 買家（或測試帳）發一則命中關鍵詞的訊息 | 桌面日誌：關鍵詞素材已注入 | ☐ |
| A3 | 確認自動發出回覆 | 買家側可見 AI 成稿（非空白）；餘額有扣減 | ☐ |
| A4 | 發一則轉人工關鍵詞 | 觸發轉接／不走 AI 硬短路 | ☐ |
| A5 | 手動關閉瀏覽器頁面 | `login_status=closed`；**不**自動重開，直到暫停／恢復自動回 | ☐ |

## B. 千牛

| # | 步驟 | 預期 | 通過 |
|---|------|------|------|
| B1 | `Test-Path apps\desktop\assets\backend\__main__.exe` 為 True | 二進位存在 | ☐ |
| B2 | 啟動千牛實例（僅允許一條懶人客服／千牛實例） | Strategy RPA 跑起；客戶端多店可切 | ☐ |
| B3 | 在對應店鋪會話發命中關鍵詞訊息 | 日誌有注入；自動回成功 | ☐ |
| B4 | 未綁 Shop／錯店時不串用他店關鍵詞素材 | 僅渠道共用或本店素材 | ☐ |

## 失敗時記錄

- 渠道：拼多多 / 千牛  
- 實例 task_id、gateway_shop_id、shop_name  
- 日誌關鍵行（關鍵詞注入／AI／發送失敗）  
- 閘道 Usage／餘額是否變動  

**硬門檻：** A3＋B3 皆通過才可對外演示／售賣。

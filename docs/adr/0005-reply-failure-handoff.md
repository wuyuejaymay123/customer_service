# ReplyFailure 走 FailureHandoff，而非靜默預設回覆

自動回覆若硬失敗、整輪發不出、或超過 ReplyTimeout（預設 60s）仍未成功發出，不得再只打日誌或塞預設句了事：須 FailureHandoff（不露餡安撫 → 盡力平台轉接 → HandoffAlert 待接管佇列），並對該會話冷卻以免與人工搶回。目的是避免買家乾等／平台超時帶來的客訴與售後。

**Considered Options**
- 靜默預設回覆／僅日誌 — 買家與運營都可能不知道失控；否決。
- 僅桌面提醒、不轉接 — 買家側仍可能無人接；否決為唯一手段（可作轉接失敗時的殘留）。
- 整實例暫停自動回 — 一單拖死整店；改為會話級冷卻。

**Consequences**
- `has_transfer` 關閉不阻止失敗轉接；規則轉人工仍受該開關約束，但同樣進待接管佇列。
- 第一版佇列本機、不落盤、不上報閘道；千牛轉接盡力，失敗加重標註。
